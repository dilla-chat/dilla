# Native Linux distributions: DEB, RPM and AUR

**2026-11-02 scope correction.** The user requested standard DEB/RPM/AUR and full release support and challenged unnecessary custom complexity with electron-builder documentation. Root adopted the recommendation in `.superpowers/sdd/2026-11-02-dilla-linux-native-packages/task-2-lifecycle-subdesign.md`. This decision supersedes the earlier native-only custom admission design and lifecycle requirements, including the linked admission design. AppImage and Windows/macOS designs remain separate and unchanged.

Use electron-builder's ordinary DEB/RPM packaging and a pinned, reviewable AUR recipe. Native package managers own installation, updates, removal and repair; app code offers signed release checks only and must never invoke electron-updater's DEB/RPM/Pacman installer methods. Compile the install kind into the application; environment variables, arguments and writable markers cannot select AppImage updater authority. Preserve authenticated Ed25519 release metadata and exact artifact hashes, ASAR integrity/fuses, Chromium sandbox, typed capabilities, enrollment, account/keyring continuity, and application quit guards for calls and drafts.

Stock `/opt/Dilla` and `/usr/bin/dilla-desktop` layout and normal builder helper permissions are acceptable. A per-application Ubuntu AppArmor profile is acceptable; do not relax global OS policy, run Electron as root, or disable its sandbox. The former native `/usr/lib/dilla/native` floor, receipt, lifetime admission lock, manager prehooks and manager-family binding are removed from this unreleased product contract. Ordinary external package-manager operations do not promise application-managed atomic rollback or an application call veto. Retain applicable AppImage and Windows/macOS recovery guarantees.

Native publishing remains blocked until exact final packages and recipe bytes are bound to release provenance and signed inventory and pass the same-run `desktop-linux-package-acceptance-{deb,rpm,aur}-x64` jobs, each with its `Installed {DEB,RPM,AUR} package acceptance` step. Each format must undergo actual normal package-manager installation, ordinary-user launch through its registered entry point, native Connect confirmation and HTTPS onboarding, observed Chromium renderer sandboxing, and installed payload equivalence to the accepted producer bytes and shipping core/client. Inspect helper modes, dependencies, desktop/protocol registration and recipe sources. The AUR recipe uses the exact DEB in makepkg's normal source cache, preserves its real SHA256 and release URL, and packages the standard Chromium helper at 4755 under pacman ownership. No source integrity, dependency or signature bypass is permitted.

**Bounded acceptance scope amendment:** Ubuntu 24.04 is the runtime baseline. Pinned official Fedora 44 and Arch userspace containers exercise their real managers with normal dependencies/signature configuration on the hosted Ubuntu kernel. The documented sandbox container option is `--cap-add=SYS_ADMIN`, retaining default Docker confinement; no privileged/unconfined container, host service/socket/home/PID mount, global policy relaxation or root Electron. These gates do not claim Fedora enforcing-SELinux or native Fedora/Arch kernel qualification. Default local-file signature policy may accept unsigned local packages; signed distribution-repository publication is not claimed. Shared Linux account/keyring/draft and normal AppImage upgrade gates remain required; duplicating an account/upgrade/failure-recovery matrix for each native format is not required. Standard managers own their lifecycle. Archive construction alone is not qualification.

The read-only CDP observer binds renderer PIDs to the owned installed browser, preserves PID start/UID identity, and requires zero effective capabilities, `NoNewPrivs=1`, `Seccomp=2` and an extra renderer seccomp filter above the browser's inherited container filters. Main-world Node globals must be absent and the main-frame Electron isolated context present. Renderer executable readlink may be blocked by sandbox nondumpability; record that limitation without a privileged reader or dumpability override, retaining CDP PID, ancestry, command-line/kernel observations and package-bound browser binary evidence. No new product instrumentation is introduced.
