# Native Linux distributions: DEB, RPM and AUR

**2026-11-02 scope correction.** The user requested standard DEB/RPM/AUR and full release support and challenged unnecessary custom complexity with electron-builder documentation. Root adopted the recommendation in `.superpowers/sdd/2026-11-02-dilla-linux-native-packages/task-2-lifecycle-subdesign.md`. This decision supersedes the earlier native-only custom admission design and lifecycle requirements, including the linked admission design. AppImage and Windows/macOS designs remain separate and unchanged.

Use electron-builder's ordinary DEB/RPM packaging and a pinned, reviewable AUR recipe. Native package managers own installation, updates, removal and repair; app code offers signed release checks only and must never invoke electron-updater's DEB/RPM/Pacman installer methods. Compile the install kind into the application; environment variables, arguments and writable markers cannot select AppImage updater authority. Preserve authenticated Ed25519 release metadata and exact artifact hashes, ASAR integrity/fuses, Chromium sandbox, typed capabilities, enrollment, account/keyring continuity, and application quit guards for calls and drafts.

Stock `/opt/Dilla` and `/usr/bin/dilla-desktop` layout and normal builder helper permissions are acceptable. A per-application Ubuntu AppArmor profile is acceptable; do not relax global OS policy, run Electron as root, or disable its sandbox. The former native `/usr/lib/dilla/native` floor, receipt, lifetime admission lock, manager prehooks and manager-family binding are removed from this unreleased product contract. Ordinary external package-manager operations do not promise application-managed atomic rollback or an application call veto. Retain applicable AppImage and Windows/macOS recovery guarantees.

Native publishing remains blocked until exact final packages and recipe bytes are bound to release provenance and signed inventory and tested in disposable Ubuntu 24, Debian 13, Fedora enforcing and pinned Arch installations. Require actual ordinary-user sandboxed client, account/keyring/draft continuity, manager-owned upgrade and remove/reinstall, failure/repair observations, and signature-policy behavior. Inspect package scripts, helper modes, dependencies, desktop registration and recipe sources. Archive construction alone is not qualification; never use `--no-sandbox` to pass acceptance.
