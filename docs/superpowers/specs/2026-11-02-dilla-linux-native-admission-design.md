# Native admission and manager handoff — revised

**Approved for the bounded contract and unprivileged bridge proof only; no privileged backend implementation or native acceptance is approved.** Native plan Task 2; incorporates controller rulings. Minimal mechanism: one main-only N-API admission bridge, persistent lock/public status, private floor/journal, standard manager hooks. No daemon, custom package-manager wrapper, process scanning/killing, AppImage/bootstrap reuse, account access or OS policy changes.

## Qualified boundary and fixed state

Use the selected standard manager with its normal database locking and enabled scripts/hooks. Permanently bind this installation to **deb, rpm or alpm**, including after removal/purge. Cross-family adoption/reinstallation is unsupported and refused, not an implicit migration. Concurrent operations of that same manager serialize across prepare, unpack and final erase; root scripts cannot defeat an administrator deliberately bypassing scripts/hooks or modifying protected files. ALPM's intact effective installed PreTransaction AbortOnFail hooks under the qualified default root hook configuration are explicit prerequisites; same-name overrides/disabling links in /etc/pacman.d/hooks must refuse startup/configuration, and unqualified custom HookDir configurations are unsupported. A removed/disabled root-owned hook is outside that prerequisite; do not claim it can abort a transaction after its own removal.

Persist `/var/lib/dilla/native-admission` root:root0755, regular `lock` root:root0644 **never replaced/unlinked**, and atomic `status.json` root:root0644. Private `/var/lib/dilla/native-sandbox` is root:root0700, records0600. Nothing in either directory is unpacked/removed as application payload. Validate fixed ancestors, effective ACL masks, no symlink/type/hardlink aliases and captured fstat identity. Qualify local filesystem flock/fsync; unsupported filesystems fail closed. Public-lock DoS causes busy refusal, never an override.

All records: format1, exact keys, strict UTF-8/duplicate-free JSON, unsigned canonical integer lexemes, safe positive generations/sizes, canonical SHA512 and UTC timestamps; maximum4096 bytes each. Fixed nullable fields below distinguish absence, not authority to reset state.

```
manager.json = {format:1,manager}
floor.json = {format:1,manager,maximumGeneration,maximumAcceptedAt,
 compatibilityEpoch:1,sandboxApi:1,helper:{size,sha512},maintainer:{size,sha512}}
receipt.json = {format:1,manager,state:"committed"|"removed",transaction,
 identitySha512,floorSha512,alpmHooks}
intent.json = {format:1,manager,operation:"install"|"remove",transaction,
 oldIdentitySha512,targetIdentitySha512,oldHelper,previousFloorSha512,targetFloor}
status.json = {format:1,manager,state:"pending"|"ready"|"removed",transaction,
 identitySha512,alpmHooks}
```

`manager` is the string enum. `transaction` is root-generated64-lowercase-hex. Digests are canonical base64 SHA512; nullable identity/floor fields represent absent old state or an unknown ALPM successor. `targetFloor` is a complete floor record, nullable only before first target admission. `oldHelper` is null or `{device,inode,size,sha512}`, with canonical decimal strings for device/inode. Each component is positive and <=8MiB. `alpmHooks` is null or `{upgradeSha512,removeSha512}` for two fixed hook files below. Ready requires identity digest and, for ALPM, both hook hashes; pending/removed have null hook tuple, removed has null public identity. Removed private receipt retains last identity/floor evidence. Floor and manager persist on purge.

Task1 package.json digest binds manager/version/channel/arch/payload/helper. Backend compiled constants pin epoch/API/helper and exact hook bytes; package scripts embed final manifest/backend hashes **after** binary/identity finalization, avoiding self-hash cycles. Same-generation helper or maintainer conflicts, lower generation and backward acceptance time reject. Persist intent's complete targetFloor before changing floor; recovery recognizes previous/target states and retains the maximum generation/time, including an accepted intent target. Unknown/corrupt contradictions hold; no automatic reset.

## Startup bridge and full-lifetime exclusion

For compiled system-package only, main synchronously invokes a tiny fixed-path Linux N-API C++ bridge **before classifier, startup-role parsing/consumption, profile/store access or account boot**. Existing Electron/C++ tooling builds it; no selectable path, arbitrary command, renderer IPC, privileges or mutation API. Load only its fixed protected package resource. The bridge verifies fixed protected ancestors, opens lock O_RDONLY|O_NOFOLLOW|O_CLOEXEC, takes SH|NB, validates public ready while held and returns its bounded snapshot. Missing/pending/removed/unknown/busy state refuses startup. Main then performs Task1 full installed-identity/payload validation and ALPM hook verification while SH remains held, before any profile use.

Keep the FD in process-wide native static storage until OS process death: no JS close/unlock, N-API cleanup hook or garbage-collection finalizer. Acquisition is idempotent and fails closed on error. Acquire a **fresh** description; never trust caller-supplied FD3 or frontend provenance. Thus direct ELF launch follows the same gate. Frontend may retain its own SH across direct exec to cover pre-JS startup, but main independently acquires its lifetime lock. No frontend-only FD is authoritative. CLOEXEC prevents normal exec children inheriting main's lock; actual Chromium fork/zygote/utility behavior must prove no surviving child lock, rather than assuming CLOEXEC covers every fork. Failure of that proof blocks qualification, not a speculative extra supervisor. Kernel locks are per open description and advisory. [flock contract](https://man7.org/linux/man-pages/man2/flock.2.html).

## Transaction order

**Prepare:** root backend requires effective UID0 and matching persistent manager, obtains EX|NB on the same inode. Busy returns before any state/payload/privilege mutation. Under EX validate/recover state, pin old helper FD eagerly, then publish/fsync public pending **before** private intent/floor or demotion. Persist/fsync intent/floor; demote old FD (SUID/SGID/capabilities), fsync it. Only then return success/release EX for manager unpack. Pending blocks every subsequent main admission. Interrupted demotion never authorizes old privilege restoration.

DEB/RPM new pre-hook calls the recognized old root-owned backend with bounded root-admin-chosen `{format:1,manager,transaction,identitySha512,helper,maintainer}` stdin target; no runtime paths/keys/network. ALPM installed pre-hook instead prepares against the **current** identity/floor, persists pending and revokes old helper before unpack; no unavailable newtuple transport. It does not advance to an unseen successor. This is an explicit refinement of the original pre-admission wording: successor admission happens after unpack, before privilege; an older successor stays0755 and held. All root script authority comes from administrator-selected packages, not app metadata signatures.

**Configure:** new root-owned backend obtains EX|NB, recovers retained maxima and verifies complete installed root-owned payload/helper0755/compiled identity. Match permanent manager and, for a prepared DEB/RPM target, exact manifest/tuple. For ALPM admit its now-observed successor. Persist candidate intent then floor before any promotion. Verify/fsync required effective hook bytes and parent directories, refusing fixed-name overrides/disabling links, before granting privilege. Promote/fsync only verified new helper FD; commit/fsync receipt; clear/fsync intent; publish/fsync public ready **last**. Crashes or failed post-scripts leave pending and require same-manager configure/reinstall satisfying retained maxima. Exact committed retries are idempotent.

**Final removal:** EX|NB, pending first, intent/floor, demote/fsync old FD, unlink/fsync helper parent, committed private tombstone, clear/fsync intent, removed public status last; all before manager erases payload. Permanent manager binding plus that same manager's database lock excludes reinstall until final erase completes, closing the former cross-family handoff hole. Post-remove never executes a removed binary. Upgrade-era old remove/abort hooks cannot demote a new committed helper or restore readiness/privilege. Aborted final removal can leave app bytes without helper; normal same-manager reinstall repairs from package bytes, not a hidden privileged backup.

## Exact manager callbacks and first installation

| Manager | Before bytes move | Commit / old hooks |
|---|---|---|
| DEB | New preinst install/upgrade prepares; prerm remove completes final removal; old prerm upgrade is inert. | New postinst configure commits; abort-* handlers and old postrm upgrade never restore privilege/ready. postrm remove/purge does no backend call/state deletion. |
| RPM | New %pre prepares; final %preun count0 removes; old upgrade %preun/%postun are inert. | New %posttrans commits after old erase, not early %post. Nonzero pre blocks that package's operation, not necessarily the whole transaction. |
| ALPM | Existing `/usr/share/libalpm/hooks/dilla-native-upgrade.hook`: Upgrade dilla-bin -> prepare-install; separate `dilla-native-remove.hook`: Remove dilla-bin -> prepare-remove. Both PreTransaction/AbortOnFail, fixed Exec, no successor input. | New .INSTALL post_install/post_upgrade configures and verifies both hook hashes/ancestors before4755/ready. .INSTALL pre failures are not the abort guarantee; remove/post-remove never restore privilege. |

For first install or removed reinstall, new backend is not yet unpacked. A small fixed-tool root pre-script creates/validates persistent gate/private parents, takes EX, and atomically creates/fsyncs manager.json with the package's literal family before returning; an existing different family refuses. Then durably publish pending; never rewrite/delete floor or existing recovery evidence. Missing backend with a live privileged helper or uncertain protected state refuses. Genuinely absent old helper needs no demotion; a previously interrupted nonprivileged0755 unpack remains held for new backend recovery after unpack. Bootstrap performs no privilege promotion. Declare required standard-tool pre-dependencies (flock, ownership/type/capability inspection, exclusive creation, atomic rename and durable sync); qualify their exact failure handling, no Python/bootstrap runtime. ALPM first-install pre-script failure may not abort unpack, but archived helper remains0755 and post-install cannot promote unless manager/gate/pending state is valid. [Debian lifecycle](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html), [RPM order](https://rpm.org/docs/latest/manual/file_triggers.html), [ALPM hook semantics](https://man.archlinux.org/man/alpm-hooks.5.en).

## Required canonical CI acceptance

Before privileged implementation approval, qualify the bridge/gate feasibility on the real fused native runtime: direct ELF admission; SH held through account lifetime/window/tray/calls/drafts and secondary forwarding; EX busy until main death; no child-held SH after main exit; pending rejects every barrier-controlled late launch. Content-free FD3 survival alone is insufficient.

Before packages qualify, real same-manager tests cover every crash/fsync/close boundary from pending through floor/demotion/unpack/promotion/receipt/ready/removal; concurrent prepare and launch; retained old-FD execution after demotion; lower/conflicting generation; first-install/abort/reinstall; stale old hooks; permanent cross-family refusal; actual profile preservation/AppImage isolation and unchanged policy. Missing/modified ALPM hooks must refuse normal startup and postconfigure where those checks run. A root-disabled/removed hook negative explicitly records **no guaranteed pre-unpack abort**, no unsupported-host qualification or new helper promotion—not a fabricated AbortOnFail result. Capture real dpkg/RPM/ALPM ordering and clean repair from each held state.
