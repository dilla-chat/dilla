# Faster CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Desktop PRs finish in about 35–45 min instead of 80–130, and releases start right after their merge. No check is lost: each moves to a tier that still runs before every release.

**Architecture:**
- desktop-gpui gets three tiers (`pr`, `nightly`, `release`), chosen by event and a dispatch input and shown in `run-name`. Heavy steps carry `if:` on the tier.
- A red nightly opens a tracking issue that blocks releases.
- `sccache` replaces the `target/` caches in every Rust CI job.
- The release gate judges runs by tree SHA and tier, and dispatches a release-tier run when none exists.
- A main push skips itself when a green PR run covered the same tree.

**Tech Stack:** GitHub Actions YAML, Node 24 scripts with `node:test` (`scripts/*.mjs`), Rust/cargo, sccache, webrtc-sys (vendored, macOS VideoToolbox).

**Spec:** `docs/superpowers/specs/2026-11-18-ci-speed-design.md` (approved by Jonas 2026-11-18).

## Global Constraints

- Tiers: `pr` (pull_request, and main pushes no green PR run covers), `nightly` (`schedule` at `0 3 * * *` UTC on main, and `workflow_dispatch` with tier=nightly), `release` (`workflow_dispatch` with tier=release).
- `run-name` is exactly `desktop-gpui [<tier>]`. It is fixed when the run starts.
- A main push that skips itself because its tree is covered is marked by its first job being named exactly `same-tree: skipped`; otherwise that job is named `same-tree: ran`.
- This deviates from the spec's `[skipped]` title because `run-name` cannot read a job output. It is recorded as a ruling and has the same effect.
- Nightly and release tiers add exactly:
  - "Run the call tests (macOS)" (`desktop-gpui.yml:228`)
  - "Run the parity screens (macOS)" (`:242`)
  - "Run the ignored tests (Linux, Bot)" (`:419`)
  - "Decode with VideoToolbox (macOS)" (`:250`, renamed from "…(macOS, nightly)")
- The PR tier keeps everything else as it is today.
- The nightly issue's title is exactly `nightly desktop-gpui red` and its label is `ci-nightly`.
- The release gate (desktop):
  - accepts only a green run titled `[nightly]` or `[release]` whose head commit's tree equals the tag's tree;
  - never accepts a run titled `[pr]` or `[skipped]`;
  - refuses while an open `ci-nightly` issue exists.
- The server gate: any green server run on the tag's tree.
- `BOUND_MS` = 150 min.
- `desktop-gpui-release.yml` and `desktop-gpui-sign.yml` build without sccache and without caches, `--locked`, unchanged.
- Every action is pinned by full commit SHA with a `# vX` comment, as everywhere in `.github/workflows`.
- Every workflow edit is mirrored in `scripts/check-ci-workflow.mjs` and its test, and in `scripts/ci-areas.mjs`. `npm run test:ci-check` must pass. Moving a check's tier is rewriting its pin, not loosening it.
- `npm run ci:local` must pass before pushing. One branch and one PR (`ci/speed`). Merging needs Jonas's go-ahead.

## Review Focus

1. **A tag whose tree only has a green `[pr]` run.** The gate must dispatch a release-tier run and wait for it, never accept the PR run. Pinned in Task 5 (`theGateNeverAcceptsAPrTierRun`).
2. **A `[skipped]` main-push run concludes `success`.** It must never satisfy the gate. Pinned in Task 5 (`aSkippedRunNeverCounts`).
3. **Main moved under the PR, so main's new tree has no green PR run.** The push must run the full PR tier, not skip. Pinned in Task 6 (`aTreeNoPrRunCoveredRunsInFull`).
4. **A PR from a fork, or a cold cache, where sccache cannot reach the GHA cache.** The build must still succeed uncached. Pinned in Task 3 (`SCCACHE_IGNORE_SERVER_IO_ERROR=1`, plus a check-ci pin).
5. **A nightly goes red, then green.** The issue opens once (or gets a comment if already open), the gate refuses meanwhile, and the next green nightly closes it. Pinned in Task 4 (`scripts/ci-nightly-issue.test.mjs`) and Task 5 (`anOpenNightlyIssueBlocksTheGate`).
