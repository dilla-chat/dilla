# dilla v0.1.0-signal1.4.1

The published build of [v0.1.0-signal1.4](v0.1.0-signal1.4.md), PR #138. The v0.1.0-signal1.4 tag has no release:
its release workflow failed in the Bot builds. This release has everything in the signal1.4 notes plus the fix
below. The release includes `dillad` (with the web client), `dillabot`, their matching core modules, installers and
checksums.

## What's fixed

- **A Bot whose YouTube sandbox can't start no longer skips the whole queue.** When the sandbox around yt-dlp failed
  to start (for example, a host where unprivileged user namespaces are blocked), every track reported "metadata
  extraction failed" and was skipped as broken. Failures before the sandboxed worker is up now pause the queue
  instead, and `dillabot doctor --youtube` reports the sandbox problem. Only failures after the worker is up count
  against the track.

## Versions and compatibility

| Component | This release | signal1.4 / realtime1 |
|---|---:|---:|
| Server database schema | 55 | 55 |
| Browser client store schema | 13 | 13 |
| Negotiated wire version (web) | 5 | 5 |

There are no new database migrations. Rolling back to realtime1 is a plain binary rollback.

## Deploy order

Follow [signal1.4's deploy order](v0.1.0-signal1.4.md#deploy-order): check that no call is live, upgrade `dillad`,
ask everyone to reload their tabs, then upgrade `dillabot` and run
`sudo -u dillabot dillabot doctor --config=/etc/dillabot/bot.toml --youtube`.
