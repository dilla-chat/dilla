# dilla v0.1.0-signal1.4.2

A hotfix release on top of [v0.1.0-signal1.4.1](v0.1.0-signal1.4.1.md). It makes pause and play on the music Bot
fast and trims the wait on every start you trigger. The release includes `dillad` (with the web client), `dillabot`,
their matching core modules, installers and checksums.

## What's fixed

- **Pause and play are fast.** Pausing used to stop the stream, so play downloaded the track again and restarted it
  from the beginning, which took about 10 seconds. Pause now holds the YouTube stream and sends silence. Play
  continues from the same second, well under 1 second later.
- **A long pause frees the stream.** After 10 minutes paused, the Bot lets go of the stream. A later play starts
  again where you paused, and takes a few seconds.
- **A Spotify pause still frees its slot.** Play restarts that Spotify track from the beginning. Spotify will be
  removed from the Bot in an upcoming release.
- **Starts you trigger go first.** Play, skip and resume after the 10-minute bound now run ahead of the Bot's
  background work. This removes a few seconds of waiting.
- **Adding a track no longer fails with a conflict** when the music panel is a little out of date. The Bot adds the
  track to the latest queue.
- **A rare warning is gone.** "sender trust refresh failed" no longer shows in the Bot's log.
- **New timing lines in the Bot's debug log.** They show where a YouTube start spends its time: sandbox ready, first
  sample and the timing of each connection. They contain no URLs or titles.

## Versions and compatibility

| Component | This release | signal1.4.1 |
|---|---:|---:|
| Server database schema | 55 | 55 |
| Browser client store schema | 13 | 13 |
| Negotiated wire version (web) | 5 | 5 |

There are no new database migrations. The Bot's saved music state keeps the same format. The only change is on
load: a state saved while playing now restarts from the beginning of the track, and a state saved while paused keeps
its place. Signal1.4.1 reads both, so rolling back to signal1.4.1 is a plain binary rollback.

## Deploy order

Follow [signal1.4's deploy order](v0.1.0-signal1.4.md#deploy-order): check that no call is live, upgrade `dillad`,
ask everyone to reload their tabs, then upgrade `dillabot` and run
`sudo -u dillabot dillabot doctor --config=/etc/dillabot/bot.toml --youtube`.

## Known limits

- A cold start still takes several seconds: the first `/play`, a skip, and the end of a track. A faster YouTube
  start and starting the next track early are planned next.
- Spotify resumes from the beginning of the track.

Otherwise the same as [signal1.4](v0.1.0-signal1.4.md#known-limits).
