# dilla v0.1.0-bot2.4

A release on top of [v0.1.0-bot2.3](v0.1.0-bot2.3.md). It carries a round of client changes in the bundled web client,
makes the Bot's music and health logs say more about what happened, and corrects three points in the operator notes.
The release includes `dillad` with the web client, the Bot and its helper. The matching desktop build is
`desktop-v0.1.0-beta.5` ([notes](desktop-v0.1.0-beta.5.md)).

There is no data migration and no manual step. If you run the Bot, upgrade `dillad` and the Bot together. The
installers do this.

## What's new

`dillad` serves the web client, so these changes arrive with the server. The desktop app carries them in beta.5.

- **The dock stays visible inside a voice channel.** The call card and the compact Now playing card no longer hide on the
  voice channel's own page.
- **The animated signal bars are gone** from the dock and the top bar.
- **Private Bot replies go away a minute after they finish.** A reply that is still working, or that offers **Retry**,
  stays. Pointing at a reply or moving focus onto it pauses the countdown.
- **A ⋯ button on the Bot card** in Server settings opens Rename, Refresh status and Disable.
- **Message times are always 24-hour** (20:27), as in the design. Dates and other times follow your system region, and
  those times are 24-hour too.
- **Voice moved to another device.** When another of your devices takes over voice, the one that lost it says
  "Voice moved to your other device." and does not rejoin.  This is the notice that bot2.3 listed as a known
  limit.
- **The poll form stays open** when the Bot's command list refreshes. If the Bot really stops offering polls, you see
  "The Bot stopped offering polls. Try again."
- **Screen sharing in the desktop app** opens a picker with thumbnails on macOS, Windows and Linux X11. Wayland keeps
  the system picker. This ships in desktop 0.1.0-beta.5, not in the web client.

## What's fixed on the server

- **A track that ends normally is no longer counted as failed.** `bot music playback ended` now carries `detail=`, one
  of `eof`, `invalid`, `cancelled`, `connection` or `helper`. A track that reaches its end is logged as `eof`. It is
  no longer counted as failed and no longer removed from the queue.
- **Repeated failed checks for new messages show in `dillad doctor`.** When the `stage=events` check fails several times
  in a row, the Bot counts one failed command, so dillad marks it degraded and `dillad doctor` shows commands failing
  since then. A failure at another stage breaks the run. The next clean check ends it, and dillad clears the mark on
  the Bot's next report with no failed commands and a passing probe, up to a minute later.

## Upgrade

This is the same as [bot2.3](v0.1.0-bot2.3.md#upgrade).

1. Take a backup with `dillad backup`.
2. Run `install.sh --upgrade`, then `install-bot.sh --upgrade`, in one window. Both restart `dilla.service`.
3. If a Bot channel never finished joining, open **Server settings → Bot** and press **Add the Bot again** on each
   channel that shows "The Bot needs adding to this channel again."
4. Check that the Bot answers. Run `/reminders list` in a Bot channel, and look for `Commands are working` in
   **Server settings → Bot**. Then run `dillad doctor`.

## Operators

None of these lines contains message content, keys, track titles or links.

- **`bot music playback ended`** carries `detail=` (see above). It never logs a track's title, link, duration or
  position.
- **`bot installation poll degraded`** (Warn) and **`bot installation poll recovered`** (Info) are logged once per
  change of state for a Bot installation.
- **Corrections to the bot2.3 notes.**
  - `bot channel group needs the Bot re-added: no Welcome to join it from` means no Welcome was found on that pass. A
    channel that keeps logging it and never logs `bot joined Bot channel group` needs **Add the Bot again**.
  - The first music item in a freshly prepared call starts with 9 stages, not 11: `call_token` and `call_fields` are
    skipped.
  - The diagnostics rule: logs carry verdicts and opaque ids, never track details.
- [Reading the Bot's journal](../README.md#reading-the-bots-journal) lists these lines.

- There is no schema change and no wire change.
- Upgrade `dillad` and the Bot together, and roll back both together. The installers do this.
- The web client changes need no action. An older desktop app keeps working against this server.

## Known limits

limit.
