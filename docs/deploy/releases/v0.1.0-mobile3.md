# dilla v0.1.0-mobile3

A release on top of [v0.1.0-mobile2](v0.1.0-mobile2.md). It is the first release that carries the Android preview app:
`dilla-v0.1.0-mobile3.apk`, signed with the project's release key, plus `dilla-v0.1.0-mobile3.apk.sha256`. Both files
are attached to this release, and the APK is listed in `SHA256SUMS`. The server and the desktop app are unchanged.

## Mobile app

- **Install on Android.** Download `dilla-v0.1.0-mobile3.apk` on your phone and allow the install when Android asks.
  If you installed the v0.1.0-mobile2 APK that was shared by hand, this one installs over it and keeps your data.
  Same signer, newer version. See [dilla on iPhone and Android](../../user/mobile.md#install).
- **iPhone.** Builds go to TestFlight once the instance owner has set up App Store Connect; ask them for the link.
- The app is still a preview. There are no push notifications, no calls in the background, and its data is not
  backed up. Keep your browser or desktop device and your recovery key.

## How this release is made

Releases are immutable once published, so `release.yml` now publishes the server release as a **draft**. The mobile
release workflow then runs from `main`: it builds and signs the APK, checks the signing certificate against the pin in
`packages/mobile/release-trust.json` and the network configuration, attaches the APK, adds it to `SHA256SUMS`, and
publishes. The signing key is only ever available to `main`'s own workflow, never to a tag. If the Android build fails,
the release stays a draft until it is fixed.

## Server

No changes. Operators: a release appears, and can be installed, only once it is published.
